# Next.js + Drizzle + Better Auth + PostgreSQL Setup Guide

A working setup guide for email/password auth with Better Auth, Drizzle ORM, and PostgreSQL running in Docker.

> Versions in this guide come from a real project (Next.js 16, React 19, `better-auth` ^1.7, `drizzle-orm` ^0.45, `drizzle-kit` ^0.31). If a command behaves differently, check the official docs for your version.

## 2. Install dependencies

```bash
npm install better-auth drizzle-orm pg dotenv
npm install -D drizzle-kit tsx @types/pg
```

Use **one** Postgres driver. This guide uses `pg` (`drizzle-orm/node-postgres`). Don't install `postgres` as well unless you use `drizzle-orm/postgres-js`.

## 3. PostgreSQL with Docker

### `docker-compose.yml`

```yaml
services:
  db:
    image: postgres:17
    restart: unless-stopped
    ports:
      - "${DB_PORT}:5432"        # host:container  (container is always 5432)
    environment:
      POSTGRES_USER: ${DB_USER}
      POSTGRES_PASSWORD: ${DB_PASSWORD}
      POSTGRES_DB: ${DB_NAME}
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${DB_USER} -d ${DB_NAME}"]
      interval: 5s
      timeout: 5s
      retries: 5

volumes:
  pgdata:
```

Key points:

- Port format is `host:container`. Postgres listens on **5432 inside** the container, so the right side must be `5432`.
- Do not set `hostname: localhost`; it's unnecessary.
- `POSTGRES_USER`, `POSTGRES_PASSWORD` and `POSTGRES_DB` are applied **only the first time** the volume is created (see Troubleshooting).
- Consider pinning an exact tag (for example `postgres:17.x-bookworm`) so the underlying OS doesn't change under an existing volume.

### `.env`

```dotenv
# Database
DATABASE_URL=postgresql://postgres:password@localhost:5433/better_auth_tutorial
DB_HOST=localhost
DB_PORT=5433
DB_USER=postgres
DB_PASSWORD=password
DB_NAME=better_auth_tutorial

# Better Auth
BETTER_AUTH_SECRET=replace-with-a-long-random-string
BETTER_AUTH_URL=http://localhost:3000
```

Generate a secret with `openssl rand -base64 32`.

Never commit `.env`. Keep a `.env.example` with placeholder values.

### Start the database

```bash
docker compose up -d
docker compose ps        # should show "healthy"
```

## 4. Drizzle setup

### `drizzle.config.ts` (project root)

```ts
import "dotenv/config";
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  dialect: "postgresql",
  schema: "./src/db/schema",
  out: "./src/db/migrations",
  dbCredentials: {
    url: process.env.DATABASE_URL!,
  },
});
```

- `import "dotenv/config"` is required: `drizzle-kit` does not read `.env` by itself.
- `schema` paths are resolved from the folder where you run the command (the project root), not from the config file location.

### `src/db/index.ts`

```ts
import "dotenv/config";
import { drizzle } from "drizzle-orm/node-postgres";
import * as schema from "./schema";

export const db = drizzle(process.env.DATABASE_URL!, { schema });
```

### `src/db/schema/index.ts`

```ts
export * from "./auth-schema";
// export * from "./posts";   // add your own tables here
```

## 5. Better Auth setup

### `src/lib/auth.ts`

```ts
import { betterAuth } from "better-auth";
import { drizzleAdapter } from "better-auth/adapters/drizzle";
import { nextCookies } from "better-auth/next-js";
import { db } from "../db"; // relative import so the CLI can resolve it
import * as schema from "../db/schema";

export const auth = betterAuth({
  emailAndPassword: {
    enabled: true,
  },
  session: {
    cookieCache: {
      enabled: true,
      maxAge: 60,
    },
  },
  plugins: [nextCookies()], // keep this as the LAST plugin
  database: drizzleAdapter(db, {
    provider: "pg",
    schema,
  }),
});
```

Requirements for the Better Auth CLI to read this file:

- It must have a **default export** or a **named export called `auth`**.
- Avoid `@/` path aliases in this file and in the files it imports (use relative imports), because the CLI runs outside Next.js.
- Avoid top-level `next/headers`, `server-only` or `"use server"` in the file that creates `auth`.
- Make sure `.env` is loaded (`import "dotenv/config"` in `src/db/index.ts`).

### API route: `src/app/api/auth/[...all]/route.ts`

```ts
import { auth } from "@/lib/auth";
import { toNextJsHandler } from "better-auth/next-js";

export const { GET, POST } = toNextJsHandler(auth);
```

### Client: `src/lib/auth-client.ts`

```ts
import { createAuthClient } from "better-auth/react";

export const authClient = createAuthClient();
```

If your app and API are on different origins, pass `baseURL` to `createAuthClient`.

Usage in a client component:

```tsx
"use client";
import { authClient } from "@/lib/auth-client";

// sign up
await authClient.signUp.email({ email, password, name });

// sign in
await authClient.signIn.email({ email, password });

// sign out
await authClient.signOut();

// session hook
const { data: session } = authClient.useSession();
```

Usage on the server (server component, route handler, server action):

```ts
import { auth } from "@/lib/auth";
import { headers } from "next/headers";

const session = await auth.api.getSession({ headers: await headers() });
```

## 6. Generate the auth schema

Add the script to `package.json`:

```json
"scripts": {
  "db:up": "docker compose up -d",
  "db:generate": "drizzle-kit generate",
  "db:migrate": "drizzle-kit migrate",
  "db:studio": "drizzle-kit studio",
  "db:push": "drizzle-kit push",
  "auth:generate": "npx @better-auth/cli@latest generate --config ./src/lib/auth.ts --output ./src/db/schema/auth-schema.ts --yes"
}
```

Then:

```bash
mkdir -p src/db/schema      # the CLI does NOT create missing folders
npm run auth:generate
```

This creates `src/db/schema/auth-schema.ts` with the `user`, `session`, `account` and `verification` tables.

Notes:

- The "Missing tables" message printed by the CLI is expected on the first run.
- `auth:generate` **overwrites** `auth-schema.ts`. Never put your own tables in that file.
- Re-run it only when you change Better Auth plugins or user fields.
- The `@better-auth/cli` package may show a deprecation warning. If the CLI fails with a version-related error, check the Better Auth docs for the current CLI command.

## 7. Create the tables

### Option A: migrations (recommended for real projects)

```bash
npm run db:generate    # creates SQL in src/db/migrations
npm run db:migrate     # applies it to the database
```

### Option B: push (fast, fine for prototypes)

```bash
npm run db:push
```

Use **either** A or B on one database, not both, or they can get out of sync.

### Verify

```bash
docker compose exec db psql -U postgres -d better_auth_tutorial -c '\dt'
```

You should see `user`, `session`, `account` and `verification`.

## 8. Adding your own tables

Put them in separate files and re-export them from `src/db/schema/index.ts`.

```ts
// src/db/schema/posts.ts
import { pgTable, text, timestamp } from "drizzle-orm/pg-core";
import { user } from "./auth-schema";

export const posts = pgTable("posts", {
  id: text("id").primaryKey(),
  title: text("title").notNull(),
  authorId: text("author_id")
    .notNull()
    .references(() => user.id, { onDelete: "cascade" }),
  createdAt: timestamp("created_at").defaultNow().notNull(),
});
```

- Better Auth's `user.id` is `text`, so foreign keys must be `text`.
- Then run `db:generate` + `db:migrate` (or `db:push`).
- `db:push` makes the database match your schema files. If a table exists in Postgres but not in any schema file, it may offer to **drop** it. Read the prompt before confirming.

## 10. Troubleshooting

### `role "xxx" does not exist`

`POSTGRES_USER`, `POSTGRES_PASSWORD` and `POSTGRES_DB` only apply when the data volume is first created. If the volume already exists with a different user, changing `.env` has no effect.

- **No data to keep:** `docker compose down -v && docker compose up -d`
- **Keep data:** connect with the original superuser and create the role, or just use that user in `.env`.

The log line "Database directory appears to contain a database; Skipping initialization" confirms this is the cause.

### Nothing answers on the database port

Check the port mapping direction in `docker-compose.yml`: it must be `"${DB_PORT}:5432"`, not `"5432:${DB_PORT}"`.

### `database ... has a collation version mismatch` (warning)

The volume was created with an older image (older glibc) than the one running now. The server works, but sort order could differ in edge cases.

- **Empty database:** `docker compose down -v && docker compose up -d`
- **Keep data:**
  ```sql
  REINDEX DATABASE better_auth_tutorial;
  ALTER DATABASE better_auth_tutorial REFRESH COLLATION VERSION;
  ALTER DATABASE template1 REFRESH COLLATION VERSION;
  ALTER DATABASE postgres REFRESH COLLATION VERSION;
  ```
  (Run `REINDEX` from another database such as `postgres` if it complains.)
- **Prevent it:** pin the image tag and avoid switching it once a volume exists.

### `Couldn't read your auth config ... default export your auth instance`

- The path in `--config` is wrong (check the real file location).
- The export is not named `auth` and is not a default export.
- The file (or something it imports) uses `@/` aliases, `next/headers` or `server-only`.
- `.env` isn't loaded, so `DATABASE_URL` is `undefined`.

### `ENOENT: no such file or directory, open './src/db/schema/auth-schema.ts'`

The output folder doesn't exist. Run `mkdir -p src/db/schema` and try again.

### `drizzle-kit`: "No schema files found" or "No schema changes"

- Make sure `schema` in `drizzle.config.ts` points to the real folder.
- "No schema changes, nothing to migrate" means your schema already matches the existing migration snapshots, so a migration was already generated.

### `drizzle-kit` can't connect

- Confirm the container is healthy: `docker compose ps`.
- Confirm `drizzle.config.ts` has `import "dotenv/config"` and uses `process.env.DATABASE_URL!`.
- Confirm `DATABASE_URL` uses the **host** port (5433 in this guide), not 5432.

## 11. Package cleanup tips

Common mistakes seen in this stack's `package.json`:

- `cn` (npm package) is **not** shadcn's helper. The `cn` helper in `lib/utils.ts` needs `clsx` and `tailwind-merge`.
- `shadcn` is a CLI. Put it in `devDependencies` or use `npx shadcn@latest`.
- Don't install both `pg` and `postgres` unless you really use both.
- For Tailwind v4 with Next.js, use `@tailwindcss/postcss` with a `postcss.config.mjs`:
  ```js
  export default { plugins: { "@tailwindcss/postcss": {} } };
  ```

## 12. Security checklist

- Use a long random `BETTER_AUTH_SECRET` and never commit it.
- Keep `.env` in `.gitignore`; commit only `.env.example`.
- Change the default `password` before deploying anywhere.
- Don't expose the Postgres port publicly in production.
- Set `BETTER_AUTH_URL` to the real production URL when deploying.


## add another tables 
No, other tables won't affect the auth tables. Just keep them in separate files.

### 1. Don't put your own tables in `auth-schema.ts`

`npm run auth:generate` **overwrites** that file every time you run it. Anything you add by hand there will be lost. Put your tables in their own files:

```
src/db/schema/
  auth-schema.ts   // generated, don't edit
  posts.ts         // yours
  index.ts         // re-exports everything
```

```ts
// src/db/schema/index.ts
export * from "./auth-schema";
export * from "./posts";
```

### 2. Reference the auth tables from yours

You can add a foreign key to `user` by importing it:

```ts
// src/db/schema/posts.ts
import { pgTable, text, timestamp } from "drizzle-orm/pg-core";
import { user } from "./auth-schema";

export const posts = pgTable("posts", {
  id: text("id").primaryKey(),
  title: text("title").notNull(),
  authorId: text("author_id")
    .notNull()
    .references(() => user.id, { onDelete: "cascade" }),
  createdAt: timestamp("created_at").defaultNow().notNull(),
});
```

Better Auth's `user.id` is `text`, so your foreign key column must be `text` too.

### 3. Use the combined schema in `db` and `auth`

```ts
// src/db/index.ts
import * as schema from "./schema";
export const db = drizzle(process.env.DATABASE_URL!, { schema });
```

```ts
// src/lib/auth.ts
import * as schema from "../db/schema";

database: drizzleAdapter(db, { provider: "pg", schema }),
```

The adapter only looks for `user`, `session`, `account` and `verification`, so your other tables don't interfere.

### 4. Keep `drizzle.config.ts` on the folder

```ts
schema: "./src/db/schema",
```

Every file in that folder is picked up, so `db:push` and `db:generate` handle auth tables and yours together.

### Two cautions

- `db:push` makes the database match your schema files. If a table exists in Postgres but not in any schema file, it may offer to **drop** it. Keep all your tables in the schema folder, and read the prompt before confirming.
- Run `auth:generate` again only when you change Better Auth plugins or user fields. Your own tables are not touched by it.
